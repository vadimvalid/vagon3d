# Вагон 3D

Эмулятор пассажирского вагона: 3D-модель с вращением и схема мест. Статический сайт без серверной части.

## Запуск

Нужен Node.js 20.19+ или 22.12+.

```bash
npm install
npm run dev      # сервер разработки, http://localhost:5173
npm run build    # сборка в dist/
npm run preview  # посмотреть собранную версию, http://localhost:4173
```

Открыть `index.html` двойным кликом больше нельзя: код разбит на модули, им нужен сервер.

## Деплой на Vercel

Настройки уже лежат в `vercel.json`: команда сборки, папка `dist`, заголовки безопасности и кэширование.

Через GitHub:

1. `git init`, закоммитьте проект и отправьте в репозиторий на GitHub.
2. На vercel.com нажмите «Add New → Project» и выберите репозиторий. Vercel сам определит Vite, менять ничего не надо.

Через CLI, без репозитория:

```bash
npx vercel          # пробный деплой
npx vercel --prod   # продакшен
```

### Адрес сайта

Адрес попадает в `canonical`, Open Graph, `sitemap.xml`, `robots.txt` и `llms.txt` во время сборки. Откуда он берётся, по порядку:

1. переменная окружения `SITE_URL`, например `https://vagon3d.ru`;
2. `VERCEL_PROJECT_PRODUCTION_URL`, её Vercel подставляет сам (это продакшен-домен проекта, в том числе свой);
3. `http://localhost:4173`, если ничего не задано.

На Vercel обычно ничего настраивать не нужно. `SITE_URL` пригодится на другом хостинге (Netlify, Cloudflare Pages, GitHub Pages): задайте её в настройках сборки. Образец в `.env.example`.

### После первого деплоя

- Откройте `/robots.txt`, `/sitemap.xml` и `/llms.txt` и убедитесь, что в них настоящий домен, а не localhost.
- Добавьте сайт в Google Search Console и Яндекс Вебмастер и отправьте `sitemap.xml`.
- Проверьте превью ссылки: картинка лежит в `public/og-image.png` (1200×630).

На превью-деплоях Vercel сам ставит `X-Robots-Tag: noindex`, в поиск они не попадут. Панель комментариев Vercel на превью не загрузится: её блокирует Content-Security-Policy. На продакшен это не влияет.

## Что внутри

- Типы вагонов: плацкартный, купейный, СВ, сидячий. Состав из 10 вагонов в полосе сверху.
- Камера: снаружи, в разрезе, сверху, из прохода (с шагом по отсекам). Поворот и масштаб мышью, пальцами, с клавиатуры и кнопками на модели.
- Выбор места кликом по схеме или по полке в 3D, вид с места, сравнение двух мест.
- Занятые места, условные цены, размеры полок, режим «Ночь», тени.
- Ссылка вида `#car-5-seat-23` открывает конкретное место.
- Настройки (вагон, тени, размеры, ночь, крыша, верхние полки) хранятся в localStorage под ключом `vagon3d:v1`.
- Справка с описанием вагонов, управлением и частыми вопросами.

## Структура

```
index.html            разметка, метаданные для поиска и соцсетей, JSON-LD, текст справки
404.html              страница «не найдено»
vite.config.js        сборка
vercel.json           деплой: заголовки, кэш
build/seo-files.js    плагин: адрес сайта в HTML, robots.txt, sitemap.xml, llms.txt
public/               иконки, манифест, картинка для соцсетей (копируются как есть)
src/
  main.js             точка входа
  app.js              действия: выбор места, смена вагона, переключатели
  store.js            состояние и сохранение настроек
  router.js           адрес #car-N-seat-M
  config.js           размеры вагона, состав поезда, названия
  model/seats.js      данные о местах: нумерация, цены, занятость (без DOM)
  ui/                 интерфейс: состав, схема, карточка, панель вида, справка
  scene/              3D на three.js
    index.js          рендер, камера, выбор мышью, свет
    kit.js            материалы, кэш геометрии, таблички
    shell.js          кузов, тележки, путь
    interior.js       полки и кресла по типу вагона
  styles/             CSS по слоям: tokens, base, layout, components, overrides
  assets/fonts/       PT Sans и PT Sans Narrow (woff2, лицензия OFL)
```

### Как устроен код

- `store.js` хранит состояние. `app.js` меняет его и вызывает обновление интерфейса и сцены. Модули `ui/` про `app.js` не знают: обработчики им передаёт `main.js`.
- Интерфейс и схема работают сразу. Сцена с three.js лежит в отдельном файле и подгружается после первой отрисовки страницы. Если WebGL недоступен, схема и карточка продолжают работать.
- Сцена рисует кадр только когда что-то изменилось. Карта теней пересчитывается только при изменении самой модели. Статичные детали склеены по материалам, чтобы вызовов отрисовки было меньше.
- Константы геометрии в `config.js`: `N` (отсеков), `BAY` (шаг отсека), `L`, `W`, `H` в метрах, ось X вдоль вагона.
- `recs` в сцене связывает номер места с мешами и точками камеры, `highlight()` красит выбранное, наведённое и занятое.

### Цвета three.js

Палитра модели подобрана без пересчёта sRGB ↔ linear, поэтому в `scene/kit.js` выключен `ColorManagement`, а яркость света умножена на π (`LIGHT`). Если включить управление цветом, все цвета и свет придётся подбирать заново.

## Доступность

- Вся работа возможна с клавиатуры. Панель вида, состав и схема мест дают по одной остановке Tab, внутри ходят стрелки.
- Выбор места, смена вагона и шаги по проходу озвучиваются через живую область.
- Занятость и выбор показаны не только цветом: зачёркнутый номер, рамка, заливка.
- Учитываются тёмная тема системы, `prefers-reduced-motion`, `prefers-contrast` и режим принудительных цветов Windows.
- Раскладка рассчитана на ширину от 320 px. Если окно слишком низкое, страница прокручивается, а не сжимает модель.

## Поддержка браузеров

Нужен WebGL 2: Chrome, Edge и Firefox последних лет, Safari 16.4+. Цель сборки в Vite: `baseline-widely-available`.

## Оговорки

Геометрия условная: размеры близки к реальным, но это не чертёж конкретной модели вагона.
Цены, занятость и состав поезда выдуманы, к реальному перевозчику отношения не имеют.
